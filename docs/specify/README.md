# Подготовка к теоретическому экзамену на водительские права в CABA

## Назначение проекта

Проект описывает локальную веб-платформу для подготовки русскоязычного пользователя к теоретическому экзамену на водительские права в Буэнос-Айресе, прежде всего в юрисдикции CABA (Ciudad Autonoma de Buenos Aires).

Целевой пользователь:

- имеет водительские права РФ;
- имеет большой практический опыт вождения;
- знает ПДД РФ;
- знает испанский язык на уровне A1 или ниже;
- хочет подготовиться именно к сдаче теоретического экзамена;
- не хочет проходить полноценный курс испанского языка или автошколу.

Основная проблема: ошибки на экзамене ожидаются не из-за отсутствия опыта вождения, а из-за локальных отличий правил, бюрократических вопросов, испанской терминологии и формулировок в билетах.

## Цель этапа specify

На этапе specify система не реализуется. Цель этапа - подготовить полный implementation plan:

- исследовать официальные источники;
- определить архитектуру решения;
- описать структуру данных и контента;
- определить pipeline обработки материалов;
- описать UX локального тренажера;
- предложить технический стек и структуру проекта;
- подготовить roadmap реализации;
- зафиксировать риски, assumptions и open questions.

## Ключевые ограничения

- Итоговая система работает полностью локально в браузере.
- После первоначальной сборки интернет не требуется.
- Backend отсутствует.
- Локальный запуск проекта должен требовать только Docker.
- Все зависимости, пакеты и tooling должны устанавливаться внутри Docker, а не в локальное окружение пользователя.
- Docker-only запуск должен валидироваться по матрице изменения из [08_local_development.md](./08_local_development.md).
- В корне проекта должен быть `Makefile` с командами `make build`, `make up` и `make down`.
- Нельзя просто встроить PDF viewer.
- Материалы должны быть переработаны в удобный web-интерфейс.
- Подготовка должна быть ultra-focused: только то, что помогает сдать экзамен.
- Не создается полноценный курс испанского языка, автошкола или энциклопедия ПДД.

## Статусы требований

Для требований, зависящих от research, используется единая маркировка:

- `defined` - подтверждено официальным источником и может использоваться в production;
- `assumed` - рабочее предположение для planning или approximate UX;
- `to_verify` - требует проверки и блокирует exact production behavior.

## Canonical Terms

Один термин должен иметь одну каноническую форму в data model, CI, validation scripts и release checklist. Русские пояснения могут использоваться в продуктовой документации, но не должны создавать альтернативные machine-readable значения.

Правила:

- canonical enum/status values пишутся на английском в `camelCase` или `snake_case` согласно schema;
- UI-лейблы и русские описания не используются как source of truth для CI;
- новый термин добавляется сюда до использования в нескольких документах;
- если термин переименован, migration note должен указать старую и новую форму.

Canonical terms:

- `source of truth` - официальный источник истины;
- `production content` - контент, разрешенный к включению в production build;
- `approval record` - машиночитаемая запись одобрения валидатором;
- `evidence bundle` - комплект доказательств для проверки контента;
- `solo self-audit` - формальная самопроверка в solo mode, не равная внешнему review;
- `solo release exception` - временное исключение для ограниченного локального или preview-релиза;
- `content availability mode` - режим доступности официальной базы вопросов;
- `official_full_bank` - полная официальная база вопросов;
- `official_sample_set` - официальный ограниченный набор вопросов, не полная база;
- `exam mode` - режим экзамена;
- `exact simulation` - точная симуляция, подтвержденная официальным форматом;
- `approximate practice mode` - приближенная тренировка без полного подтверждения формата;
- `Docker-only flow` - запуск, сборка и проверки без установки проектных зависимостей на хост.

## Definition of Success

Система считается успешной, если пользователь с минимальным испанским и без глубокого изучения аргентинского ПДД может за короткий срок:

- понимать экзаменационные билеты;
- распознавать типовые испанские формулировки;
- знать локальные отличия от ПДД РФ;
- тренироваться на официальных вопросах;
- отслеживать ошибки и слабые темы;
- быть готовым к успешной сдаче теоретического экзамена в CABA.
