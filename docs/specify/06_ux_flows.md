# UX Flows

## UX Principles

- Пользователь уже умеет водить, поэтому интерфейс не должен объяснять базовые вещи.
- Главный фокус - экзаменационная готовность.
- Испанский текст всегда остается первичным.
- Русский перевод и объяснение помогают понять, но не заменяют оригинал.
- Переключение между языками должно быть быстрым.
- Слабые темы должны всплывать автоматически.

## Onboarding

Первый экран должен помочь выбрать режим:

- `Учить билеты`;
- `Сдать пробный экзамен`;
- `Повторить ошибки`;
- `Словарь`;
- `Отличия от ПДД РФ`.

Onboarding должен кратко объяснить:

- что официальные формулировки не изменяются;
- что перевод и комментарии неофициальные;
- что проект ориентирован на CABA.

## Learning Mode

В режиме обучения вопрос показывает:

- официальный испанский текст;
- варианты ответов;
- кнопку показа русского перевода;
- кнопку показа объяснения;
- ключевые испанские слова;
- тему;
- источник;
- jurisdiction.

После ответа:

- показать правильный ответ;
- объяснить причину;
- подсветить ключевые слова;
- предложить открыть связанные термины;
- предложить добавить вопрос в сложные.

## Exam Mode

Режим экзамена должен имитировать реальные условия настолько, насколько это известно из официальных источников.

Параметры exam mode должны читаться из `content/config/caba-exam-format.json`, а не задаваться в UI-коде. Нужно определить и подтвердить официальным source record:

- количество вопросов;
- таймер;
- passing score;
- правила завершения;
- возможность пропуска вопроса;
- порядок вопросов.

Если официальный формат неизвестен или config имеет статус `assumed` / `to_verify`, интерфейс должен явно пометить симуляцию как приближенную. Exact simulation label допустим только при статусе `defined`.

В exam mode по умолчанию:

- не показывать перевод;
- не показывать объяснения;
- не показывать правильный ответ до завершения;
- фиксировать время ответа.

После завершения:

- показать score;
- показать ошибки;
- показать темы ошибок;
- предложить повторение слабых тем.

## Vocabulary Mode

Словарь должен поддерживать:

- группировку по темам;
- поиск по испанскому и русскому;
- примеры из билетов;
- отметку critical terms;
- повторение терминов;
- связь с вопросами.

## Guide Mode

Методичка должна быть короткой и практической:

- отличия от ПДД РФ;
- бюрократические темы;
- частые ловушки;
- high-priority темы;
- ссылки на вопросы.

## Search and Filters

Фильтры:

- тема;
- jurisdiction;
- сложность;
- ошибочные вопросы;
- избранное;
- вопросы с отрицаниями;
- вопросы с бюрократическими темами;
- вопросы, где пользователь открывал перевод;
- вопросы, где пользователь ошибся больше одного раза.

Поиск:

- испанский текст;
- русский перевод;
- термины;
- темы;
- источники.

## Mobile UX

Mobile-first требования:

- крупные touch targets;
- sticky progress/timer в exam mode;
- быстрый toggle перевода;
- компактный режим карточки;
- отсутствие перегруженных таблиц;
- удобный повтор ошибок.

## Desktop UX

Desktop может использовать two-pane layout:

- слева вопрос и ответы;
- справа перевод, объяснение, словарь и источник;
- быстрые горячие клавиши для выбора ответа.

## Accessibility

Минимальные требования:

- keyboard navigation;
- semantic HTML;
- достаточный contrast;
- понятные focus states;
- отсутствие зависимости только от цвета;
- поддержка screen reader labels для кнопок.
