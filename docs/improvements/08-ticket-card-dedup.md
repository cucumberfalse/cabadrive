## 1. Контекст и проблема

**Две параллельные реализации карточки вопроса**: интерактивный QuestionCard (App.tsx:448-670) и статический CanonicalStudyTicketBlock (App.tsx:1090-1180) дублируют одну структуру — question-meta (554-561 vs 1121-1126), official-block с испанским текстом (537-550 vs 1127-1130), блок перевода (590-594 vs 1131-1141), изображение (596-603 vs 1142-1149), список ответов с подсветкой правильного (629+ vs 1156-1174). Изменение отображения билета вносится дважды (и уже разошлось: role="listitem" есть только в статической версии — App.tsx:1156-1164 vs 629-647).

**Два ридера мануала**: легаси Manual4RuedasView (App.tsx:3229+, достижим только через недокументированный `?legacyManual=1`, App.tsx:3964, в навигации отсутствует — App.tsx:4077-4087) и актуальный IntroductionSectionsView (App.tsx:3007) дублируют поиск/навигацию/выбор страницы.

**QuestionCard «полуконтролируемый»**: локальные selected/showTranslation/showExplanation (473-475) дублируют attemptState и ресинхронизируются через useEffect (487-491); объект attemptState вручную собирается в 3 местах (504-508, 522-526, 613-617).

## 2. Цели

1. Одна реализация карточки билета из компонуемых частей.
2. Принято и исполнено решение по легаси-ридеру.
3. QuestionCard — полностью контролируемый компонент с одним источником истины.

## 3. Требования

- FR-1: Presentational-компоненты `TicketMeta`, `OfficialTextBlock`, `TranslationAside`, `TicketImage`, `AnswerList` (проп `interactive: boolean`); обе карточки собираются из них.
- FR-2: QuestionCard: attemptState — единственный источник истины; локальные useState и ресинхронизирующий useEffect удалены (LearnView/MistakesView уже хранят attemptsByQuestion; ExamView хранит своё).
- FR-3: Решение по Manual4RuedasView (предлагается **удалить**: ≈370 строк + чанк-логика + `?legacyManual=1`; постраничный просмотр покрыт IntroductionSectionsView и «Источниками»). Если удержание — обязателен пункт навигации и общий поиск с актуальным гидом ([ТЗ-P1](./priority/01-usability.md) FR-G5).
- NFR-1: Видимый DOM карточек не меняется (кроме исправления непоследовательного role="listitem" — привести обе к одному, см. ТЗ-P1 FR-E2).

## 4. План

- [ ] 1. Выделить 5 presentational-компонентов; собрать CanonicalStudyTicketBlock
- [ ] 2. Пересобрать QuestionCard на них + контролируемый режим
- [ ] 3. Решение по легаси-ридеру (RFC-комментарий в PR) → удаление или интеграция
- [ ] 4. Синхронное обновление source-matching тестов

## 5. Критерии приёмки

- AC-1: Разметка билета определена в одном месте (grep official-block по src — один компонент).
- AC-2: В QuestionCard нет useEffect-ресинхронизации (App.tsx:487-491 удалён).
- AC-3: e2e зелёные; при удалении легаси — удалены его e2e-упоминания и чанк-исключение в generate-service-worker.mjs:10-12.

## 6. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Тонкие различия карточек потеряются при унификации | Средняя | Регрессия UI | Таблица различий ДО рефакторинга; e2e-скрины |
| Легаси-ридер кому-то нужен | Низкая | Потеря функции | Проверить аналитику/спросить владельца до удаления; вернуть легко (git) |
