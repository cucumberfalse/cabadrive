## 1. Контекст и проблема

Для iOS в index.html нет ни apple-touch-icon, ни apple-мета (grep «apple» по репо — 0 вхождений); без манифеста «На экран Домой» даёт скриншот-иконку и обычную Safari-вкладку (манифест — [ТЗ-12](./12-pwa-installability.md)). Критичнее: Safari агрессивно чистит хранилище — SW-регистрация и Cache Storage неиспользуемого ~7 дней сайта удаляются (ITP), ~40 МБ прекеша — первый кандидат на eviction при нехватке места. Вместе с кешем может быть выселен и **localStorage с прогрессом** (`cabadrive.progress.v1`, src/storage.ts) — потеря всей истории подготовки. В src нет ни `navigator.storage.persist()`, ни `estimate()` (grep подтверждает) — приложение даже не запрашивает persistent-статус и не может предупредить пользователя.

## 2. Цели

Минимизировать вероятность потери оффлайн-кеша и прогресса на iOS/Android; пользователь видит статус оффлайн-данных.

## 3. Требования

- FR-1: После регистрации SW вызывается `navigator.storage.persist()`; результат (granted/denied) сохраняется и отображается в статусе.
- FR-2: `navigator.storage.estimate()` → индикатор «Материалы для оффлайна: X МБ из Y доступных» в StatusStrip/настройках.
- FR-3: Прогресс дублируется в IndexedDB (переживает часть сценариев очистки localStorage; лёгкая обёртка без библиотеки — один object store) с восстановлением из копии при пустом localStorage; источник истины — progressStore ([ТЗ-06](./06-progress-store.md)).
- FR-4: iOS-пользователям (детект standalone === false && iOS UA) показывается ненавязчивая подсказка «Добавьте на экран Домой — материалы сохранятся дольше».
- FR-5: Экспорт прогресса файлом — страховка последней инстанции (UI — [ТЗ-P1](./priority/01-usability.md) FR-A3; здесь — напоминание о экспорте при denied-персистентности).
- NFR-1: Никаких внешних зависимостей (idb-обёртка своя, ~50 строк).

## 4. План

- [ ] 1. persist()/estimate() + статус в UI
- [ ] 2. IndexedDB-зеркало прогресса + восстановление + unit-тесты (fake-indexeddb в node --test)
- [ ] 3. iOS-подсказка A2HS
- [ ] 4. Напоминание об экспорте при denied

## 5. Критерии приёмки

- AC-1: На поддерживающих браузерах после первого визита storage.persisted() === true (или показан denied-статус).
- AC-2: Очистка localStorage при живом IndexedDB → прогресс восстановлен при следующей загрузке (unit/e2e с evaluate).
- AC-3: Индикатор объёма отображает данные estimate() (e2e: наличие узла со значением).

## 6. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Safari игнорирует persist() без установки | Высокая | Ограниченный эффект | Подсказка A2HS (FR-4) + экспорт (FR-5) — многослойная защита |
| Рассинхронизация двух хранилищ | Средняя | Конфликт версий | Зеркало пишется из единственной точки progressStore; timestamp решает |
