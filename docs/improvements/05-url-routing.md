## 1. Контекст и проблема

«Роутинг» приложения — это `useState<View>` (App.tsx:3960-3966) с условным рендером десяти вью (App.tsx:4089-4105). URL-адресуем только раздел «Руководство» (view="pandemia") через ручной `window.location.hash` + `history.pushState` и слушатели hashchange/popstate (App.tsx:3980-4003, 4031-4058). Остальные 8 вью теряются при перезагрузке/шаринге; легаси-ридер мануала достижим только через недокументированный `?legacyManual=1` (App.tsx:3964). Ручная hash-логика продублирована в трёх функциях selectView/selectIntroductionEntry/selectManualSection с повторяющимся сравнением pathname+search+hash (App.tsx:4037, 4040, 4049, 4057). popstate принудительно сбрасывает не-pandemia вью в learn (App.tsx:3995) — кнопка «Назад» браузера фактически не работает.

Пользовательские последствия и требования к поведению описаны в [ТЗ-P1](./priority/01-usability.md) (FR-G1..G3); здесь — технический дизайн.

## 2. Цели

1. Все 10 вью и ключевые под-состояния адресуемы URL; Back/Forward работают везде.
2. Ручная hash-механика централизована в одном модуле; существующие hash-маршруты «Руководства» сохранены байт-в-байт (закреплены e2e).

## 3. Не-цели

- Библиотека роутинга: для 10 плоских маршрутов + существующей hash-схемы собственный модуль на ~100–150 строк проще и не тянет зависимость. (Если в будущем появятся вложенные лейауты — пересмотреть в пользу wouter.)
- Server-side маршруты (SPA на nginx с fallback остаётся как есть).

## 4. Требования

- FR-1: Модуль `src/router.ts`: `type Route`, `parseRoute(location): Route`, `routeUrl(route): string`, хук `useRoute(): [Route, (r: Route) => void]`, инкапсулирующий hashchange/popstate/pushState.
- FR-2: Схема: `#/learn`, `#/exam`, `#/mistakes`, `#/vocabulary`, `#/materials`, `#/process`, `#/caba-rf`, `#/sources`, `#/sources/<docId>`, `#/manual`, `#/manual/<pageId>`; существующие intro/pandemia-хэши парсятся как алиасы своего Route без переименования.
- FR-3: Пустой hash → learn (текущее поведение). Неизвестный hash → learn без исключений.
- FR-4: `?legacyManual=1` либо мапится на `#/manual` (redirect с history.replaceState), либо удаляется вместе с легаси-ридером — по решению [ТЗ-08](./08-ticket-card-dedup.md).
- FR-5: Фильтры «Источников» (категория/тип/режим текста) — в query-части hash (`#/sources/<docId>?cat=...`), восстановление при загрузке.
- NFR-1: Существующие e2e hash-сценарии «Руководства» проходят без правок.

## 5. Предлагаемое решение и план

- [ ] 1. `src/router.ts` + unit-тесты parseRoute/routeUrl (node --test, чистые функции)
- [ ] 2. App: замена useState<View> на useRoute; selectView → setRoute; удаление трёх дублирующихся pushState-блоков
- [ ] 3. Перенос intro/pandemia-хэшей на parseRoute-алиасы (поведенчески идентично)
- [ ] 4. Под-состояния: sources docId, manual pageId, фильтры
- [ ] 5. aria-current="page" на активной вкладке; e2e на Back/Forward/перезагрузку

## 6. Критерии приёмки

- AC-1: Перезагрузка на каждой из 9 вкладок возвращает на неё (e2e-цикл по вкладкам).
- AC-2: Back после перехода A→B возвращает на A (e2e).
- AC-3: Ссылка `#/sources/<docId>` открывает документ на чистом профиле (e2e).
- AC-4: Все существующие e2e зелёные без правок hash-ожиданий «Руководства».
- AC-5: В App.tsx нет прямых обращений к window.location/history вне router.ts (grep).

## 7. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Расхождение с закреплёнными e2e-хэшами | Средняя | Красный CI | Алиасы вместо переименования; прогон e2e до PR |
