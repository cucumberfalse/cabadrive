# Анализ репозитория Cabadrive

Дата анализа: 2026-07-11. Audited revision: `bd0ce1dd3e367f07db8528248f9cb00e2b296441`. Метод: многоагентный аудит — 6 параллельных карт подсистем, анализ по измерениям (архитектура, PWA/оффлайн, юзабилити, документы, изображения, тестирование, пайплайн, инфраструктура, документация), точечные измерения (разрешения изображений, гистограммы, размеры бандла/контента), консолидация в 22 ТЗ. Наблюдения и измерения ниже описывают этот снимок, а не гарантируют состояние более поздних ревизий.

## 1. Что это за проект

Cabadrive — local-first веб-тренажёр для русскоязычных водителей, готовящихся к теоретическому экзамену CABA (Буэнос-Айрес). Контент: 460 неофициальных билетов категории B (из Apache-2.0 комьюнити-источника), русский интерактивный гид по официальному 200-страничному мануалу GCBA (50 секций), переводы официальных первоисточников (19 документов), словарь, режимы «Учить»/«Экзамен»/«Ошибки». Репозиторий также содержит развитую мульти-агентную инфраструктуру разработки («Unicorn Hub»: роли агентов, worktree-процесс, 5 обязательных CI-гейтов, feature memory в specs/ с 50 фичами).

## 2. Архитектура и стек

- **Фронтенд**: React 19 + Vite 6 + TypeScript (strict), без роутера и state-библиотек; весь UI в `src/App.tsx` (4108 строк, ~40 компонентов), стили в одном `src/styles.css` (4744 строки). «Роутинг» — useState с 10 вью; URL-адресуемо только «Руководство».
- **Данные**: статический контент-корпус в git (content/, 316 МБ, 2915 файлов); JSON импортируется в бандл (частью eager, частью лениво), бинарные ассеты копируются в public/. Прогресс пользователя — localStorage.
- **Сборка/деплой**: pnpm-скрипты → Vite → кастомный генерируемый service worker (прекеш всего dist); двухстадийный Docker (node:22-alpine → nginx:1.29-alpine); e2e — Playwright (Desktop Chrome + Pixel 7).
- **Тесты**: 31 файл контент-гейтов на node --test (~502 теста), 51 e2e-тест ×2 проекта; компонентных тестов нет; typecheck/линтера/форматтера нет.
- **Пайплайн контента**: ~35 Node ESM-скриптов валидации/генерации + 3 macOS-only Swift-скрипта (рендер PDF, кропы, каталог знаков); sha256-пины и byte-exact evidence.

## 3. Обзор подсистем (карты аудита)

### Фронтенд
Монолит App.tsx со смешением данных и представления (словари ярлыков, геометрии инфографики в коде); дублирование карточки билета (QuestionCard vs CanonicalStudyTicketBlock) и двух ридеров мануала; ~24-веточная if-диспетчеризация контент-блоков; тяжёлые вычисления в рендере без useMemo; потеря локального состояния вью при переключении табов; весь eager-контент (~4 МБ JSON) в стартовом чанке.

### Данные и контент
Шардированные переводы/объяснения (5 диапазонов по 92 вопроса) с канонической валидацией; ленивы только primary sources (50 шардов) и мануал (чанк с layout.ru.json 7,4 МБ). 316 МБ распределены: validation 105 МБ (QA-evidence), official-documents 77 МБ (PDF), assets 71 МБ (раздаваемые), primary-sources 31 МБ. Всё в git без LFS → .git 433 МБ.

### Сборка, деплой, оффлайн
SW прекеширует ~40 МБ атомарным cache.addAll (обрыв одного запроса = нет оффлайна, молча); skipWaiting+удаление кешей ломает lazy-чанк у открытых вкладок; фолбэк fetch-обработчика содержит мёртвый код (`|| после Promise`); PWA-манифеста и иконок нет — приложение не устанавливается. nginx: immutable на НЕ-хешированных путях контента (инвертированная политика), нет security-заголовков и gzip.

### Тестирование и CI
Сильная контентная валидация, но App.tsx проверяется только e2e и хрупкими регэксп-тестами по исходнику. В CI нет tsc --noEmit/ESLint/Prettier/coverage. baseline-checks делает полный build дважды, validate:content по 316 МБ — трижды; Playwright без retries (trace никогда не пишется); только chromium-движок.

### Контент-пайплайн
Ядро validate-content.mjs (sha256-пины, сквозные ссылки, дисклеймеры) + 4 аудита manual-guide. Хрупкость: дублированные canonicalJson/sha256 (расхождение тихо ломает все пины), монолиты с данными в коде (manual-sign-inventory.mjs 4627 строк), macOS-only Swift-генерация, зависимость валидации от specs/, захардкоженные даты ревью в генераторах.

### Документация и процесс
Вся документация агентно-ориентированная (AGENTS.md 229 строк, ролевая модель, SENAR-гейты); для конечного пользователя — ничего. README дезинформирует («no product runtime scaffold»). **Нет LICENSE при Apache-2.0 upstream-контенте — юридический риск публикации.** Дублирующиеся номера фич в specs/ (002×3, 019×3, 032×3).

## 4. Сильные стороны

- Дисциплина контента: sha256-пины, сквозные ссылки вопрос↔перевод↔объяснение↔источник, дисклеймеры неофициальности принудительно валидируются.
- Обширные e2e (5348 строк, включая офлайн-перезагрузку и «no external requests») и docker-смоук.
- Чистая доменная логика вынесена в src/domain.ts и покрыта тестами.
- Продуманная мобильная схема список↔деталь, широкий focus-visible, touch-таргеты 42–58 px.
- Развитый процесс PR-гейтов, воспроизводимость контент-артефактов.

## 5. Ключевые проблемные зоны

Полный список — [README](./README.md). Критические:

1. **Потеря данных пользователя** — сброс прогресса без подтверждения, гибель экзаменационной попытки при переключении вкладки → [ТЗ-P1](./priority/01-usability.md).
2. **Юридический риск** — отсутствие LICENSE/атрибуции Apache-2.0 → [ТЗ-22](./22-license-attribution-docs.md).
3. **Размытые изображения** — рендер страниц при 144 DPI, кропы уже колонки в 2-3 раза, фото билетов 574 px → [ТЗ-P3](./priority/03-image-quality.md).
4. **Декоративный strict-TS** — нет typecheck/линтера в CI → [ТЗ-16](./16-quality-tooling.md).
5. **Хрупкий оффлайн** — атомарный 40 МБ прекеш, ломающее обновление SW → [ТЗ-13](./13-service-worker-reliability.md).
