## 1. Контекст и проблема

1. В ExamView `finish()` вызывается **внутри функции-апдейтера** setTimeRemaining (App.tsx:879-886) — сайд-эффект (запись в localStorage, setState) в state updater, который StrictMode/concurrent-рендер может вызвать дважды; защита — только флаг finished (App.tsx:910) и `window.clearInterval(timer)` изнутри апдейтера (881). Интервал пересоздаётся на каждый ответ из-за deps `[answers, finished]` (App.tsx:889) — answers нужен лишь замыканию finish.
2. Состояние учебной сессии — sessionQuestions (перетасовка на маунте, App.tsx:708), attemptsByQuestion, timerStates (App.tsx:706-707) — локальный useState LearnView, гибнет при unmount: «Учить → Словарь → Учить» перетасовывает вопросы и сбрасывает ответы/таймеры сессии.
3. У таймера билета три источника истины: timerStates, attemptsByQuestion и restoredTimerState (App.tsx:718-723).

Пользовательские требования (персист попытки экзамена, продолжение сессии) — [ТЗ-P1](./priority/01-usability.md) FR-A4, FR-A6; здесь — техдизайн.

## 2. Цели

Таймеры не зависят от пересозданий интервала и StrictMode; состояние сессий переживает переключение вкладок; у каждого таймера один источник истины.

## 3. Требования

- FR-1: ExamView: дедлайн-модель — хранится `endTime` (absolute ms); тик вычисляет remaining; effect с deps `[finished]` при remaining ≤ 0 вызывает finish **вне апдейтера**; answers для finish — из ref или reducer.
- FR-2: Состояние сессии LearnView (seed порядка + индекс + attempts) выносится в модуль сессии (sessionStorage; часть progressStore или отдельный sessionStore) — восстановление при повторном маунте.
- FR-3: Таймер билета: состояние деривативно из attemptState + startedAt; параллельный Record timerStates удаляется.
- FR-4: Персист активной экзаменационной попытки `{questionIds, answers, startedAt, endTime}` — общий механизм с FR-1 (дедлайн-модель делает восстановление тривиальным).
- NFR-1: Поведение таймеров в e2e не меняется (существующие сценарии таймера зелёные).

## 4. План

- [ ] 1. ExamView: дедлайн-модель + стабильный интервал + unit-тест finish-идемпотентности
- [ ] 2. Персист попытки + восстановление (совместно с ТЗ-P1 слайс 2)
- [ ] 3. sessionStore для LearnView + поиск по sessionQuestions
- [ ] 4. Таймер билета: один источник истины

## 5. Критерии приёмки

- AC-1: В src нет вызовов функций с сайд-эффектами внутри state-апдейтеров (ревью + grep setTimeRemaining).
- AC-2: StrictMode-двойной рендер не дублирует finish (unit с имитацией двойного вызова).
- AC-3: «Учить → Словарь → Учить» сохраняет вопрос и порядок (e2e).
- AC-4: Перезагрузка в экзамене → корректный остаток времени по endTime (e2e, с clock-контролем Playwright).

## 6. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Смена системного времени ломает endTime | Низкая | Неверный остаток | Клампить remaining в [0, длительность]; допустимо |
| Конфликт с ТЗ-04 (этап 5) | Средняя | Merge | Выполнять до или в составе переноса ExamView |
