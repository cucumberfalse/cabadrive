## 1. Контекст и проблема

SW генерируется [generate-service-worker.mjs](../../scripts/generate-service-worker.mjs) поверх dist. Четыре связанные проблемы (все строки проверены):

1. **Монолитный атомарный прекеш более 40 МБ.** `cache.addAll(ASSETS)` одним куском; исключены `sw.js` и большой корпус постраничных JPG, но feature 049 сознательно включает все хешированные `/assets/`, в том числе deferred `manual4Ruedas` JS. Это гарантирует, что старая открытая вкладка впервые загрузит свой старый чанк уже после деплоя новой версии, однако увеличивает установочный трафик и объём сохраняемых version caches. Обрыв ЛЮБОГО обязательного запроса отменяет установку целиком и сохраняет предыдущую готовую версию. Двухфазность/reuse и отображение частичного статуса остаются FR-1/FR-2/FR-5.
2. **Обновление открытых вкладок (исходный риск, закрыт feature 049).** Первый переход со старого cache-first worker выполняется автоматически только после полного прекеша и записи с повторным чтением фиксированного маркера `prompted-activation-v1` в отдельном `cabadrive-update-protocol-v1` cache: старая страница ещё не умеет показать баннер. Наличие маркера навсегда возвращает обычный режим — следующие worker ждут явного `Обновить`. Старые Cabadrive version caches сохраняются, инициирующая вкладка делает один reload, а другие вкладки только очищают устаревший баннер. Неограниченное хранение и повторное скачивание хешированных assets приняты как временный correctness-first компромисс до FR-1/FR-2.
3. **Fetch-обработчик (исходные баги закрыты features 048/049).** Навигация теперь идёт network-first с `cache: "no-store"`, а при сбое/неуспешном ответе использует только полностью установленный shell текущего worker с query-insensitive fallback. Субресурсы никогда не получают HTML fallback: current cache → retained Cabadrive cache → network → `Response.error()`.
4. **Закоммиченный public/sw.js расходится с генерируемым**: кладёт в кеш любой GET-ответ без проверки response.ok (public/sw.js:22-24 — закешированный 404 отдаётся вечно), прекеш только ["/", "/index.html"], имя кеша v1 навсегда. Если dist задеплоят без шага generate:sw — в прод молча уйдёт деградированный SW; ни один тест не сверяет два SW.

## 2. Цели

1. Установка оффлайна устойчива к обрыву отдельных запросов; деплой докачивает только изменённое.
2. Обновление SW не ломает открытые вкладки; пользователь видит «Доступна новая версия».
3. Fetch-обработчик корректен для навигаций и субресурсов.
4. Невозможен молчаливый деплой деградированного SW.

## 3. Требования

- FR-1: Двухфазный прекеш: критичный app shell (index.html, JS/CSS-бандлы, manifest) — атомарный addAll; контент-ассеты — пофайлово `Promise.allSettled` в фоне после activate, с отчётом (postMessage) о доле закешированного.
- FR-2: Reuse при install: совпадающие URL копируются из предыдущего кеша (для контент-хешированных путей — по URL; после [ТЗ-P3](./priority/03-image-quality.md) хешированными станут и картинки).
- FR-3: Цикл обновления: убрать безусловный skipWaiting; в main.tsx — onupdatefound → state «installed» при живом controller → баннер «Доступна новая версия — обновить»; по клику postMessage {type:"SKIP_WAITING"} и на controllerchange — location.reload(); периодический registration.update() (раз в час, SPA без навигаций сам sw.js не перепроверяет).
- FR-4: Fetch: `caches.match(request, { ignoreSearch: request.mode === "navigate" })`; catch-ветка: для navigate — `(await caches.match("/")) ?? (await caches.match("/index.html")) ?? Response.error()`; для остальных — Response.error().
- FR-5: Статус установки оффлайна виден в UI (StatusStrip: «Оффлайн готов: 100 %» / «частично»); ошибки регистрации не глотаются молча.
- FR-6: public/sw.js заменяется тонким no-op SW (только skipWaiting, без fetch-обработчика) + тест «dist/sw.js после сборки ≠ public/sw.js» (маркер CACHE_NAME) — защита от деплоя без generate:sw.
- FR-7: Unit-тесты текста генерируемого SW расширяются: фолбэк-ветки, ignoreSearch, двухфазность (сейчас tests/service-worker-generation.test.mjs:63-79 проверяет только наличие addAll/fetch/put).
- NFR-1: Рассмотреть Workbox как альтернативу самописному генератору (precache-манифест с ревизиями закрывает FR-1/FR-2 из коробки); решение зафиксировать в PR — если самописный остаётся, FR-1..FR-4 обязательны.

## 5. Критерии приёмки

- AC-1: Обрыв одного контент-запроса при установке (эмуляция route.abort в e2e) не лишает оффлайна app shell.
- AC-2: После деплоя открытая вкладка получает баннер; клик обновляет без битых чанков (e2e с двумя сборками).
- AC-3: Оффлайн-запрос отсутствующей картинки возвращает сетевую ошибку, не HTML (unit текста SW + e2e).
- AC-4: Повторный деплой с одним изменённым файлом докачивает ≤ 5 % прежнего объёма (замер route-логом e2e).
- AC-5: Сборка без generate:sw ловится guard-тестом.

## 6. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Двухфазный прекеш усложняет самописный SW | Средняя | Баги | Серьёзно рассмотреть Workbox (NFR-1); полный unit-охват текста SW |
| Баннер обновления раздражает | Низкая | UX | Показывать не чаще раза в сессию; «позже» откладывает |
| reuse-кеш отдаст устаревший непроверенный файл | Низкая | Стейл-контент | Reuse только для хешированных путей |
