## 1. Контекст и проблема

Стартовый JS-бандл несёт весь eager-контент: src/data/content.ts:317-324 собирает переводы и объяснения через `import.meta.glob(..., {eager: true})` (~1,5 МБ JSON), туда же — 460 вопросов (~1,2 МБ), topic-study-guide (1,3 МБ), learning-images runtime (content.ts:326-339). src/data/manualGuide.ts:1-51 статически импортирует все 50 модулей manual-sections с полным русским контентом гида, а App.tsx импортирует manualGuide верхнеуровнево (App.tsx:34-41) — всё в основном чанке. vite.config.ts настроек сборки не содержит (только plugins+server). Ленивы только два корпуса: primarySources.ts и manual4Ruedas (динамический import, App.tsx:3239; layout.ru.json 7,4 МБ в этом чанке — парсинг заметен на слабых устройствах). Время первой загрузки растёт линейно с каждым новым разделом контента, хотя на старте пользователь видит только LearnView.

## 2. Цели

Стартовый чанк содержит только код и контент критического пути (LearnView: вопросы+переводы+объяснения); остальные разделы грузятся по требованию.

## 3. Не-цели

Ручной manualChunks-тюнинг (React.lazy по вью даст сплит автоматически); оптимизация самого manual4Ruedas-чанка (отдельная задача при необходимости).

## 4. Требования

- FR-1: После декомпозиции ([ТЗ-04](./04-app-tsx-decomposition.md)) вью TopicGuideView, IntroductionSectionsView (+manualGuide.ts с 50 секциями), PrimarySourcesView, ProcessGuideView, GuideView — React.lazy + Suspense (fallback — существующий паттерн загрузки).
- FR-2: manualGuide.ts импортируется только из IntroductionSectionsView → контент гида уходит в его чанк.
- FR-3: Прекеш-правила generate-service-worker.mjs обновлены: ленивые чанки вью прекешируются (они нужны оффлайн!), но отдельно от app shell — согласованно с [ТЗ-13](./13-service-worker-reliability.md) (пофазный прекеш).
- FR-4: Бюджет стартового чанка фиксируется тестом: dist/assets/index-*.js ≤ порога (замерить после сплита, заложить +10 %); тест по образцу существующих build-тестов.
- NFR-1: Оффлайн-режим не деградирует: все чанки в SW-кеше после установки (e2e офлайн-перезагрузки остаётся зелёным).

## 6. Критерии приёмки

- AC-1: Стартовый чанк уменьшился ≥ 40 % (ожидание: уходит ~1,3 МБ topic guide + ~1,3 МБ manual-sections; фактический порог зафиксировать замером).
- AC-2: Переход на «Материалы»/«Руководство» показывает контент без сетевых ошибок (e2e), оффлайн — тоже.
- AC-3: Бюджет-тест в CI падает при превышении порога.

## 7. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Лишний lazy-чанк недоступен после деплоя у открытых вкладок | Высокая | Ошибка import | Решается циклом обновления SW — [ТЗ-13](./13-service-worker-reliability.md); до него — chunk-error-retry с reload |
| Suspense-мигание при быстрой сети | Низкая | UX | Fallback с задержкой ~150 мс |
