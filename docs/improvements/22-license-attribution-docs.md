## 1. Контекст и проблема

1. **Нет LICENSE** — при этом банк из 460 вопросов взят из Apache-2.0 upstream (комьюнити-симулятор bandinopla/simulador-test-de-conducir; зафиксировано в content/meta и специфике источника `source-bandinopla-testdeconducir-b`). Apache-2.0 требует сохранения лицензии и атрибуции — **публичный репозиторий (репо публичен, 9 звёзд) и любой деплой без файла лицензии upstream нарушают условия**. Статус лицензии собственного кода тоже не определён — форк/использование юридически подвешены.
2. **README вводит в заблуждение**: строка «No product runtime scaffold is committed yet» (README.md:21) давно неверна — приложение полностью реализовано; ключевая точка входа дезинформирует и людей, и агентов.
3. Нет CONTRIBUTING.md, SECURITY.md, CHANGELOG; нет документации для конечного пользователя (продукт для русскоязычных водителей, но ни описания режимов, ни скриншотов, ни инструкции запуска для не-разработчика).
4. Дополнительно зафиксировано (для будущего решения, вне скоупа): дублирующиеся номера фич в specs/ (002×3, 019×3, 032×3 и др.), machine-specific пути в process memory.

## 2. Цели

Юридическая чистота публикации; точка входа в репозиторий отражает реальность; пользователь понимает, что это и как этим пользоваться.

## 3. Требования

- FR-1: LICENSE собственного кода — выбор владельца (рекомендация: MIT или Apache-2.0; Apache-2.0 упрощает совместимость с upstream). Решение фиксируется в PR.
- FR-2: `NOTICE`/раздел «Атрибуция» в README: источник банка вопросов (ссылка на upstream-репозиторий, его Apache-2.0), копия текста лицензии upstream в `licenses/` (или NOTICE-файл по формату Apache-2.0); указание, что официальные материалы GCBA/BORA используются как первоисточники с соблюдением их условий (проверить условия перепубликации фрагментов мануала GCBA — отметить в NOTICE итог проверки).
- FR-3: README переписывается: (а) что это за продукт и для кого (1 абзац, RU+EN), (б) скриншоты 2-3 ключевых экранов, (в) быстрый старт пользователя (URL или docker compose up), (г) быстрый старт разработчика (существующие команды), (д) актуальная структура репо; строка «no product runtime scaffold» удаляется.
- FR-4: CONTRIBUTING.md — краткий: указатель на AGENTS.md-процесс, preflight, правило «PR only»; SECURITY.md — контакт для сообщений об уязвимостях.
- FR-5: Пользовательская страница «О приложении» в UI (route #/about или секция в «Процессе»): версия, источники контента с дисклеймерами (тексты уже есть в content/meta/content-mode.json), ссылка на репозиторий, атрибуция.
- NFR-1: Дисклеймеры «неофициальности» банка вопросов, уже принудительно проверяемые validate-content.mjs, не ослабляются.

## 4. План

- [ ] 1. FR-1 + FR-2 (LICENSE, NOTICE, licenses/) — юридический минимум, один быстрый PR
- [ ] 2. FR-3 (README со скриншотами)
- [ ] 3. FR-4 (CONTRIBUTING, SECURITY)
- [ ] 4. FR-5 (страница «О приложении»)

## 5. Критерии приёмки

- AC-1: В корне есть LICENSE и NOTICE; licenses/ содержит Apache-2.0 upstream; атрибуция видна в README.
- AC-2: README не содержит устаревших утверждений (ручная вычитка); скриншоты отображаются на GitHub.
- AC-3: Страница «О приложении» доступна из UI и содержит атрибуцию (e2e-проверка наличия).

## 6. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Условия перепубликации материалов GCBA неочевидны | Средняя | Юридический | Отдельный пункт проверки в FR-2; при сомнении — консультация и пометка в NOTICE |
| Выбор лицензии требует решения владельца | Гарантированно | Блокер FR-1 | PR открывается с рекомендацией и вопросом к владельцу |
