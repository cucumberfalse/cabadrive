## 1. Контекст и проблема

Приложение (9 экранов-вкладок, весь UI в [App.tsx](../../../src/App.tsx), 4108 строк) функционально богато, но UX-аудит по коду выявил 18 проблем: семь более серьёзных ниже, из которых две — критические потери данных пользователя, и одиннадцать средней/низкой серьёзности. Сводка ключевых фактов (все проверены по коду, строки указаны):

- **Сброс всего прогресса — одним тапом без подтверждения**: кнопка RotateCcw в шапке (App.tsx:4070-4072) вызывает `reset()` → `clearProgress()` → `localStorage.removeItem` (App.tsx:4026-4029, storage.ts:44-46). Ни confirm, ни undo, ни экспорта (grep `confirm(` по App.tsx — 0 совпадений). Один случайный тап стирает все ответы, ошибки и попытки экзамена.
- **Экзаменационная попытка молча гибнет**: всё состояние ExamView — локальный useState (App.tsx:864-874); переключение вкладки размонтирует компонент (App.tsx:4090), перезагрузка — то же. Прогресс пишется только в `finish()` (App.tsx:909-924). Нет beforeunload, нет guard-диалога, нет персиста активной попытки. Вдобавок экзамен стартует мгновенно при клике на вкладку — таймер запускается в useEffect на маунте (App.tsx:876-889), случайный клик = потерянная попытка.
- **«Пропустить» = скрытый штраф**: `skipCurrent()` записывает `{selectedAnswerId: "", isCorrect: false}` (App.tsx:898-907), вернуться нельзя (App.tsx:891-896), скипы попадают в историю (App.tsx:919) и навсегда становятся «ошибками» в mistakesFromHistory (domain.ts:70-82) — при том что формат экзамена CABA подразумевает отложенные вопросы (`canSkipQuestion: true` в content/config/caba-exam-format.json).
- **Ошибки никогда не закрываются**: фильтр `stat.wrong > 0` (domain.ts:78-81) кумулятивен — правильные повторные ответы в режиме «Ошибки» ни на что не влияют; обещанный в docs_project/screens/learning-and-exam-flows.md:58 «track repeated-error reduction» не реализован.
- **8 из 9 вкладок не в URL**: view — useState (App.tsx:3959-3966), hash есть только у «Руководства»; перезагрузка выбрасывает в «Учить», Back не работает (App.tsx:3995), deep-link невозможен.
- **Тёмной темы нет**: 0 вхождений prefers-color-scheme (styles.css, index.html); при этом `theme-color #12312b` тёмный (index.html:6) — строка браузера тёмная, страница белая. Для вечерней зубрёжки — типичного сценария — белый `#fffefa` на OLED слепит.
- **Поиск по билетам не находит диакритику**: search.ts:20-27 — голый toLowerCase, «senal» не найдёт «señal»; при этом в manual/sources нормализация есть (App.tsx:257-262) — два разных поведения поиска в одном приложении. Топики в haystack — английские слаги (search.ts:10), а UI обещает поиск по теме на русском (App.tsx:826).
- Плюс 11 проблем средней/низкой серьёзности: тупиковый флаг «Сложный» (кнопка в MistakesView — `onToggleDifficult={() => undefined}`, App.tsx:998), обрезка списка ошибок до 12 (App.tsx:978), результат экзамена без разбора и CTA (App.tsx:926-936), таймер без предупреждения об истечении (App.tsx:940-944), потеря позиции сессии обучения (App.tsx:704-723), 9 вкладок в горизонтальном скролле на мобильном (styles.css:171-182), потеря фокуса при переключении список↔деталь (App.tsx:3730-3735, styles.css:4313-4318), псевдо-кликабельные ответы после ответа (App.tsx:497-498, 629-647), h2 внутри role="button" (App.tsx:537-550), пустой словарь без empty state (App.tsx:1022-1043), расхождение с задуманными экранами (нет Home/онбординга; Manual4RuedasView спрятан за ?legacyManual=1, App.tsx:3964).

Позитив, который сохраняем: touch-таргеты 42–58 px, широкое focus-visible, продуманная мобильная схема список↔деталь, корректный сброс скролла при навигации, e2e-фиксация manual-сценариев.

## 2. Цели

1. Ноль сценариев безвозвратной потери данных пользователя без явного подтверждения.
2. Каждая вкладка и ключевые под-состояния адресуемы URL (перезагрузка/Back/шаринг работают).
3. Экзаменационный поток соответствует реальному экзамену CABA (отложенные вопросы, стартовый экран, предупреждения таймера, разбор результата).
4. Раздел «Ошибки» даёт ощущение прогресса (ошибки закрываются повторными правильными ответами).
5. Единое поведение поиска во всех разделах (диакритика, русские темы).
6. Тёмная тема; базовые a11y-дефекты устранены.

## 3. Не-цели

- Декомпозиция App.tsx (техническая предпосылка — [ТЗ-04](../04-app-tsx-decomposition.md); данное ТЗ можно выполнять до, после или параллельно, по одному слайсу).
- Новые режимы обучения (spaced repetition и т. п.) — отдельный продуктовый бэклог.
- Редизайн визуального стиля.
- Улучшение качества изображений — [ТЗ-P3](./03-image-quality.md).

## 4. Текущее состояние

Описано в §1; дополнительные факты для исполнителя:
- Прогресс: `src/storage.ts` (46 строк) хранит только `answers[]`, `difficultQuestionIds[]`, `examAttempts[]` под ключом `cabadrive.progress.v1`. Паттерн «setProgress + saveProgress» продублирован в 4 местах (см. [ТЗ-06](../06-progress-store.md)).
- Роутинг: hash-механика «Руководства» закреплена e2e-тестами (tests/e2e/app.spec.ts) — её менять нельзя, только расширять.
- Медиазапросы: 840/760/380 px; вкладки на <760 px уходят в overflow-x: auto без индикатора (scrollbar-width: thin, на iOS невидим).
- Empty states есть в LearnView/MistakesView (role="status"), в VocabularyView — нет.

## 5. Требования

Функциональные (сгруппированы по темам А–Е):

**А. Сохранность данных**
- FR-A1: Сброс прогресса требует подтверждения в модальном диалоге с перечислением удаляемого (N ответов, M ошибок, K попыток экзамена) и текстовым вводом или двойным подтверждением.
- FR-A2: После сброса доступна отмена (undo) до конца сессии: снапшот в `sessionStorage` + кнопка «Вернуть» в тосте/статус-панели.
- FR-A3: Экспорт/импорт прогресса файлом JSON (кнопки рядом со сбросом; экспорт — Blob+download, импорт — валидация схемы через существующую логику loadProgress).
- FR-A4: Активная экзаменационная попытка переживает перезагрузку и переключение вкладок: персист `{questionIds, answers, startedAt, deadline}` в localStorage; при возврате — предложение «Продолжить попытку (осталось MM:SS)» / «Отменить».
- FR-A5: Уход с вкладки «Экзамен» при активной попытке — подтверждающий диалог; закрытие вкладки браузера — beforeunload.
- FR-A6: Сессия обучения (порядок-seed, позиция) персистится в sessionStorage; возврат на «Учить» продолжает с того же вопроса.

**Б. Экзаменационный поток**
- FR-B1: Стартовый экран экзамена (формат: 40 вопросов, 45 мин, проходной 85 %, правила скипа) с кнопкой «Начать» — таймер до нажатия не идёт.
- FR-B2: «Пропустить» откладывает вопрос в очередь (возврат после основного прохода), не записывает isCorrect:false; незавершённые к концу времени скипы фиксируются как неотвеченные отдельным статусом `skipped`, не попадающим в mistakesFromHistory.
- FR-B3: Таймер: при ≤5 мин exam-bar меняет цвет (--amber), при ≤1 мин — --danger; aria-live="polite" объявление; на экране результата — пометка «время истекло», если finish вызван по таймеру.
- FR-B4: Экран результата: разбивка ошибок по темам (topicLabel), список неверных вопросов с раскрытием, CTA «Разобрать ошибки» (переход в mistakes) и «Новая попытка» (сброс локального стейта без размонтирования-трюка).

**В. Работа над ошибками и флаг «Сложный»**
- FR-V1: Ошибка «закрывается» после 2 подряд правильных ответов на вопрос (порог — константа); закрытые отображаются в отдельной свёрнутой группе «Закрытые (N)» зачёркнуто/приглушённо.
- FR-V2: Список ошибок в сайдбаре — полный, со скроллом (max-height + overflow-y по образцу .source-list); усечение slice(0,12) удаляется.
- FR-V3: Флаг «Сложный» получает применение: фильтр/режим «Сложные» (переиспользовать механизм MistakesView), счётчик в StatusStrip; в MistakesView прокинут настоящий toggleDifficult вместо `() => undefined`.

**Г. Навигация**
- FR-G1: Все 9 вкладок адресуемы hash-маршрутами (#/learn, #/exam, ...); Back/Forward переключают вкладки; существующие hash-и «Руководства» сохраняются без изменений (обратная совместимость с e2e).
- FR-G2: Под-состояния адресуемы: выбранный документ в «Источниках» (#/sources/<docId>), страница мануала. Фильтры — в query-части hash.
- FR-G3: Активная вкладка помечена aria-current="page".
- FR-G4: Мобильная навигация: видимый индикатор продолжения (edge-fade градиент) у скроллируемых вкладок ИЛИ группировка второстепенных разделов в «Ещё» (выбор за исполнителем после прототипа; fade — дешевле, «Ещё» — системнее).
- FR-G5: Решение по скрытым экранам: Manual4RuedasView либо получает пункт навигации, либо удаляется (согласуется с [ТЗ-08](../08-ticket-card-dedup.md)); лёгкий Home-экран (карточки режимов + сводка прогресса) реализуется ИЛИ docs_project/screens приводится в соответствие с реальностью.

**Д. Поиск**
- FR-D1: `normalizeSearchText` (NFD + strip diacritics) переносится из App.tsx:257-262 в src/search.ts и применяется к query и haystack поиска билетов и словаря.
- FR-D2: Haystack билетов включает русские метки тем (topicLabel), а не только слаги.
- FR-D3: LearnView получает фильтры: тема (select), сложность, «с картинкой»; поиск идёт по sessionQuestions (сохранение порядка сессии), а не по data.questions.

**Е. Обратная связь, a11y, тема**
- FR-E1: Тёмная тема: палитра :root переопределяется в `@media (prefers-color-scheme: dark)` + ручной переключатель (light/dark/auto) с персистом; `color-scheme: light dark`.
- FR-E2: После ответа неактивные варианты — disabled/aria-disabled + визуальное приглушение; семантика вариантов — radiogroup (role="radio", aria-checked) или удаление role="list"; статус верно/неверно дублируется текстом для скринридера.
- FR-E3: Переключение список↔деталь (<760 px) переводит фокус на заголовок открывшейся панели (tabIndex={-1} + ref.focus()) — «Источники», manual-ридер.
- FR-E4: Блок испанского текста вопроса: явный видимый аффорданс раскрытия перевода (шеврон/кнопка «Показать перевод»), h2 выносится из role="button".
- FR-E5: VocabularyView: empty state по образцу LearnView; термины связываются с примерами билетов (sourceQuestionIds), как обещано в docs_project.

Нефункциональные:
- NFR-1: Ни одно изменение не ломает существующие e2e-сценарии (5348 строк app.spec.ts) — прогон обязателен на каждый слайс.
- NFR-2: Новые интерактивные элементы соответствуют текущим паттернам фокуса (focus-visible) и touch-таргетам ≥42 px.
- NFR-3: Диалоги подтверждения — доступны с клавиатуры (фокус-ловушка, Esc, автофокус на безопасной кнопке).

## 6. Предлагаемое решение (дизайн по темам)

- **Диалоги (FR-A1/A5)**: один переиспользуемый `<ConfirmDialog>` на `<dialog>`-элементе (нативная фокус-ловушка + Esc бесплатно); стилизация под существующие панели. Не тянуть UI-библиотеку.
- **Персист попытки (FR-A4)**: ключ `cabadrive.exam-attempt.v1`; дедлайн хранить как absolute timestamp (`deadline = startedAt + 45*60_000`) — восстановление корректно после перезагрузки; тик таймера вычисляет remaining из дедлайна (заодно чинит хрупкий finish-в-апдейтере, см. [ТЗ-11](../11-timers-session-state.md)).
- **Очередь скипов (FR-B2)**: `skippedIds: string[]` в состоянии попытки; после последнего основного вопроса position идёт по очереди; в `finish()` неотвеченные скипы получают `status: "skipped"` — требуется расширение типа записи ответа (поле опционально, обратная совместимость с loadProgress) и фильтра в domain.ts:mistakesFromHistory.
- **Закрытие ошибок (FR-V1)**: domain.ts — вместо кумулятивного `wrong > 0` считать по хвосту истории: последние 2 записи по questionId верны → resolved. Функция чистая, покрывается unit-тестом.
- **Роутер (FR-G1/G2)**: свой модуль `src/router.ts` (~100 строк): `parseRoute(location): Route`, `routeUrl(route): string`, хук `useRoute()` с hashchange/popstate. Обоснование против react-router: 10 плоских маршрутов + обязательная совместимость с существующей ручной hash-механикой «Руководства» — детальный дизайн в [ТЗ-05](../05-url-routing.md), выполнять этот пункт одним слайсом с ним.
- **Тёмная тема (FR-E1)**: палитра уже на CSS-переменных в :root — добавить блок переопределений + `[data-theme="dark"]`/`[data-theme="light"]` атрибут на html, переключатель в шапке, персист в localStorage (`cabadrive.theme`), meta theme-color обновлять из JS.
- **Поиск (FR-D1-D3)**: правки search.ts — экспорт normalizeSearchText, предвычисление haystack один раз (Map questionId→haystack, контент статичен — см. также [ТЗ-09](../09-search-layer-memoization.md)).

## 8. Критерии приёмки

- AC-1: Тап по «Сбросить прогресс» не удаляет данные без подтверждения; после подтверждения доступна «Вернуть» до конца сессии; экспортированный JSON импортируется на чистом профиле с полным восстановлением (e2e).
- AC-2: Перезагрузка страницы посреди экзамена → предложение продолжить с корректным остатком времени и ответами (e2e).
- AC-3: Пропущенный и не отвеченный вопрос не появляется в «Ошибках»; пропущенный и отвеченный в конце — учитывается по фактическому ответу (unit + e2e).
- AC-4: Вопрос с ошибкой исчезает из активного списка после 2 подряд правильных ответов и виден в группе «Закрытые» (unit + e2e).
- AC-5: Перезагрузка на любой вкладке возвращает на неё же; Back переключает вкладки; ссылка #/sources/<docId> открывает документ (e2e, оба проекта Desktop+Pixel 7).
- AC-6: Поиск «senal» находит вопросы с «señal»; поиск «стоянка» находит вопросы темы parking (e2e).
- AC-7: prefers-color-scheme: dark даёт тёмную палитру без нечитаемых сочетаний (ручная проверка контраста ключевых пар ≥ 4.5:1); переключатель персистится.
- AC-8: axe-scan (или ручной VoiceOver-прогон по чеклисту) ответов вопроса: состояние выбран/верно/неверно объявляется; неактивные варианты не в фокус-порядке.
- AC-9: Существующие e2e (51 тест на проект, 102 запуска в двух проектах) зелёные после каждого слайса.
- AC-10: План и итоговые PR явно трассируют все 18 проблем исходного UX-аудита: семь более серьёзных и одиннадцать средней/низкой серьёзности; ни одна проблема не теряется при разбиении на восемь слайсов.

## 9. План тестирования

- Unit (node --test, паттерн data:-URI как в tests/domain.test.mjs): mistakesFromHistory с resolved-логикой; статусы skipped; parseRoute/routeUrl; экспорт/импорт схемы прогресса.
- E2e: новые сценарии на каждый AC (соседство с существующими в app.spec.ts); обязательный прогон обоих проектов.
- Ручной: VoiceOver-чеклист (ответы, диалоги, переключение панелей); контраст тёмной темы; iOS Safari — видимость edge-fade.
