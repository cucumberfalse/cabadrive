| Категория | Контент / переводы / читабельность |
| Оценка трудоёмкости | L |
| Статус | Предложено |

## 1. Контекст и проблема

Ядро продукта — русскоязычное «Руководство»: 50 секций учебника GCBA в [src/data/manual-sections/](../../../src/data/manual-sections/) (главы ch1–ch5, приложения app1–app4, front matter) + интро-раздел pandemiaVialSection. Контент структурирован блоками (распределение по corpus'у, измерено grep: 157 `list`, 46 `lead`, 44 `callout`, 32 `paragraph`, 29 `source-image-cards`, 17 `source-image-original-visible-text`, 10 `table`, 7 `official-traffic-sign-source-as-is`, 6 `manual-sign-catalog`, 5 `glossary-list` и ~25 одиночных специализированных видов). Русские переводы связаны с испанскими первоисточниками полями `sourceTextEs` и постранично (`sourcePages`), качество частично контролируется четырьмя аудитами `scripts/manual-guide-*.mjs`.

Проблемы, найденные аудитом:

1. **Три несвязанных источника терминологии.** Терминологические решения зашиты прямо в код аудита ([manual-guide-translation-completeness-audit.mjs:45-60](../../../scripts/manual-guide-translation-completeness-audit.mjs) — массив `terminologyDecisions`: «carriles de aceleración → полосы разгона» и т. д.), отдельно живёт глоссарий секции front-glossary (`src/data/manual-sections/front-glossary.ts`, blocks kind `glossary-list`), отдельно — пользовательский словарь `content/vocabulary/ru.vocabulary.json` (всего **10 терминов** при сотнях экзаменационных терминов в корпусе). Ничто не проверяет, что термин переведён одинаково во всех 50 секциях, вопросах и словаре.
2. **Типографика русского текста не нормирована.** Во всех 50 секциях **ни одного длинного тире** (grep ` — ` по src/data/manual-sections — 0 совпадений); вместо тире используется дефис: «Скорость - это отношение расстояния ко времени» (ch3-speed.ts, блок speed-definition). Кавычки, неразрывные пробелы перед «км/ч», ё/е — не проверяются ничем.
3. **Аудит полноты перевода — точечный, а не сплошной.** `requiredProbeTerms` в manual-guide-translation-completeness-audit.mjs:34-44 — 11 проб для одной тематики (автомагистрали); `sourceTextEs` в блоках хранится усечённо (с «...», см. ch3-speed.ts) — аудит не может сверить полноту передачи испанского текста, только наличие проб и терминов из списка.
4. **Слабая связность чтения.** Прогресса чтения нет (grep «Прочитано/reading-progress» по App.tsx — 0); оглавление с иерархией есть у легаси-ридера (`manual-toc`, App.tsx:3450) и «Источников» (`source-toc`, App.tsx:3905), а актуальный гид имеет только плоскую навигацию `manual-guide-nav`. Связь «страница учебника → билеты» реализована ([manualTicketPlacement.ts](../../../src/data/manualTicketPlacement.ts): questionId→pageIds, недавние коммиты «Add reviewed tickets to manual pages»), обратной связи «билет → секция учебника» в карточке вопроса нет.
5. **17 блоков `source-image-original-visible-text` + 29 `source-image-cards`** показывают испанский текст картинками; их читаемость зависит от разрешения кропов (см. [ТЗ-P3](./03-image-quality.md)), а переводы подписей контролирует image-readability-аудит — но табличные/списочные вставки, которые МОЖНО передать русским текстовым блоком (`table`/`list`), остаются картинками.
6. **Орфография не проверяется ничем** — ни spellcheck в CI, ни в аудитах (только терминологические пробы).

## 2. Цели

1. Единый машиночитаемый глоссарий — единственный источник терминологии; консистентность всех 50 секций + вопросов + словаря проверяется автоматически.
2. Русский текст корпуса типографически нормирован (тире, кавычки, неразрывные пробелы) и проверяется автоматически.
3. Сплошной (не точечный) контроль полноты перевода секций.
4. Читатель видит прогресс по учебнику и связь секций с билетами в обе стороны.
5. Орфографическая проверка в CI.

## 3. Не-цели

- Пересмотр самой методики source-fidelity (соответствие источнику — существующие аудиты сохраняются).
- Повышение разрешения картинок-вставок — [ТЗ-P3](./03-image-quality.md).
- Расширение пользовательского словаря как продуктовой фичи (связь терминов с билетами — [ТЗ-P1](./01-usability.md), FR-E5).
- Переводы новых документов-первоисточников.

## 4. Текущее состояние

- Секция = TS-модуль с типом `ManualGuideSectionContent`: `titleRu`, `sourcePages[]`, `sourceTitleEs`, `status`, `visualEvidence` (скриншоты + sha-пины), `blocks[]` (у блока: `id`, `kind`, `sourceTextEs` (усечённый), `textRu`/`itemsRu`/`rows` и т. п.).
- Цепочка `pnpm run validate:manual-guide` = source-fidelity → visual-completeness → image-readability-translations → translation-completeness; все читают TS-исходники через компилятор TypeScript (`ts.transpileModule`-подход) и пишут evidence в content/validation.
- Терминологический контроль: `terminologyDecisions` (пары es→ru) + `requiredProbeTerms` в теле скрипта; глоссарий гида — front-glossary.ts; словарь UI — ru.vocabulary.json (10 записей).
- Типографика чтения в порядке (колонка 72–74ch, styles.css:222, 1088) — менять не требуется.

## 5. Требования

Функциональные:
- **FR-1**: Создан `content/glossary/ru.glossary.json` — канонический глоссарий: `[{ termEs, termRu, aliasesEs[], aliasesRu[], note, sourcePages[] }]`; naполнен слиянием трёх существующих источников (terminologyDecisions + front-glossary + vocabulary) с ручной выверкой конфликтов.
- **FR-2**: Новый аудит `scripts/manual-guide-terminology-audit.mjs`: для каждого termEs, встречающегося в `sourceTextEs` любой секции, соответствующий русский текст блока содержит termRu (или алиас); нарушения — списком с sectionId/blockId. Подключён в `validate:manual-guide`.
- **FR-3**: `terminologyDecisions`/`requiredProbeTerms` удаляются из кода аудита переводов и читаются из глоссария (обратная совместимость evidence — перегенерация с `--write`).
- **FR-4**: Типографический аудит `scripts/manual-guide-typography-audit.mjs`: (а) ` - ` в русских полях → ошибка «дефис вместо тире»; (б) программные кавычки `"` в русском тексте → «использовать „ёлочки“»; (в) отсутствие NBSP в «NN км/ч», «NN м» — предупреждение; (г) двойные пробелы. Однократная нормализация корпуса — вспомогательным скриптом с `--write` (sed-класс замен + ручное ревью diff).
- **FR-5**: Аудит полноты: для каждой секции покрытие `sourcePages` блоками — каждый source-page имеет ≥1 блок (или явную запись-исключение с причиной в секции); отчёт «страница без контента».
- **FR-6**: Прогресс чтения: пометка «прочитано» на секции (по кнопке или scroll-в-конец), сводка в навигации гида («Глава 3: 5/8»); хранение — расширение progress-хранилища (согласовано с [ТЗ-06](../06-progress-store.md)).
- **FR-7**: Обратные ссылки: в карточке вопроса (QuestionCard) — ссылка «Раздел учебника: <titleRu>» по обратному индексу manualTicketPlacement (pageId→sectionId у секций уже есть через sourcePages).
- **FR-8**: Инвентаризация 17+29 картинок-вставок с текстом: каждой присваивается disposition `keep-as-image` (фото, схемы) либо `convert-to-text-block` (таблицы, списки); конверсии выполняются партиями с сохранением source-fidelity evidence.
- **FR-9**: Spellcheck в CI: cspell с русским и испанским словарями (`cspell-dict-ru_ru`, `cspell-dict-es_es`) по `src/data/manual-sections/**`, `content/vocabulary/**`, `content/translations/**`; проектный словарь исключений `cspell-project-words.txt` (топонимы CABA, термины DNRPA и пр.).

Нефункциональные:
- **NFR-1**: Все новые аудиты — по образцу существующих (ESM, `--write` для evidence, канонический JSON) и включены в `validate:content`.
- **NFR-2**: Нормализация типографики не изменяет испанские поля (`sourceTextEs` неприкосновенен — это цитаты источника).
- **NFR-3**: Время новых аудитов суммарно ≤ 5 с (порядок существующих).

## 6. Предлагаемое решение

- Глоссарий — контент, а не код: JSON в content/ проходит существующий канонический-JSON-контроль свежести; аудиты и UI (словарь, подсказки в гиде) читают один файл. Матчинг терминов — по нормализованному тексту (существующий normalizeSearchText: NFD, без диакритики), по границам слов, с учётом испанских множественных форм через `aliasesEs`.
- Типографический нормализатор: консервативные замены только в русских полях (`textRu`, `itemsRu`, `cellsRu`, `captionRu`, `titleRu`): ` - ` → ` — `; парные `"..."` → `«...»`; числовые пары `(\d) (км/ч|м|кг|с)` → NBSP. Прогон один раз с ручным ревью диффа (ожидаемый объём — сотни строк), далее аудит держит норму.
- Полнота: `sourcePages`-покрытие вычислимо из существующих полей блоков `data-source-page` (при их отсутствии в типе блока — добавить обязательное поле sourcePage в схему блока при следующем расширении).
- Конверсия вставок (FR-8): использовать существующие типы блоков `table`/`list`; source-fidelity-аудит уже умеет привязку к странице; картинка-оригинал остаётся в visualEvidence секции (доказательная база не худеет).

## 7. План реализации

- [ ] **Этап 1**: глоссарий (FR-1) + терминологический аудит (FR-2) + перевод существующего аудита на глоссарий (FR-3); перегенерация evidence
- [ ] **Этап 2**: типографический аудит + одноразовая нормализация корпуса (FR-4); ревью диффа носителем языка
- [ ] **Этап 3**: аудит полноты покрытия страниц (FR-5); закрытие найденных дыр контентом или исключениями
- [ ] **Этап 4**: cspell в CI (FR-9); чистка находок; проектный словарь
- [ ] **Этап 5**: прогресс чтения (FR-6) + обратные ссылки билет→секция (FR-7)
- [ ] **Этап 6**: инвентаризация и конверсия картинок-вставок (FR-8), партиями по главам

## 8. Критерии приёмки

- AC-1: `manual-guide-terminology-audit.mjs` завершает 0 на корпусе; намеренная подмена «полосы разгона» на «полосы ускорения» в любой секции — ловится (негативный тест).
- AC-2: grep ` - ` по русским полям src/data/manual-sections — 0; grep ` — ` — сотни (визуальная проверка 3 случайных секций — тире уместны).
- AC-3: В коде аудитов нет литеральных терминологических пар (grep terminologyDecisions — только чтение глоссария).
- AC-4: Отчёт полноты: 100 % sourcePages покрыты блоками или задокументированными исключениями.
- AC-5: cspell-джоб зелёный в CI; словарь исключений ≤ 300 записей (иначе — разбор).
- AC-6: На странице гида с привязанными билетами виден блок билетов (уже есть) И из карточки такого билета — ссылка на секцию (новое, e2e).
- AC-7: Прочитанная секция помечается в навигации; сводка «N/M» по главе; состояние переживает перезагрузку (e2e).
- AC-8: Каждая картинка-вставка имеет disposition; конвертированные таблицы проходят source-fidelity.

## 9. План тестирования

- Unit: терминологический матчер (диакритика, множественное число, границы слов); типографические замены (не трогает sourceTextEs, NBSP-правила).
- Негативные фикстуры для обоих аудитов (tests/manual-guide-terminology-audit.test.mjs по образцу существующих).
- E2e: прогресс чтения, обратные ссылки.
- Ручное: вычитка диффа нормализации; выборочная проверка глоссария против PDF-источника.

## 10. Риски и меры

| Риск | Вероятн. | Влияние | Мера |
|---|---|---|---|
| Слияние трёх терминологических источников выявит конфликты переводов | Высокая | Ручная работа | Конфликты — таблицей на ревью; правило: приоритет глоссария front-glossary как самого проработанного |
| Автозамена типографики заденет код/испанский | Низкая | Порча цитат | Замены только в перечисленных русских полях через AST (ts-morph/компилятор, как в аудитах), не sed по файлу |
| Массовая правка 50 секций → конфликт с параллельной контент-работой | Средняя | Merge-ад | Этап 2 — одним быстрым PR, скоординированным по времени |
| cspell даст сотни ложных срабатываний на терминах | Высокая | Шум | Стартовый прогон в report-only, наполнение словаря до включения в required |
| Конверсия вставок исказит источник | Средняя | Fidelity-регрессия | Оригинал остаётся в visualEvidence; двойное ревью против PDF |
