# Backend Docs

## Backend Decision

No runtime backend is part of the current product. Cabadrive is intentionally local-first and offline-capable after build.

## Data And Storage Model

- Content is bundled as static assets generated by the content pipeline.
- User progress is stored locally. The current implementation uses a localStorage-backed adapter; IndexedDB remains the planned upgrade if data volume or structured querying requires it.
- No server database, queue, or cloud sync is present in the current product.

## API Surface

There are no runtime network APIs. Data-processing scripts for ingest/validation/export are repository tooling, not user-facing backend services.

Current tooling:

- `scripts/validate-content.mjs` validates content mode, source hashes, exam config, category B fallback constraints, local question images, disclaimers, guide/vocabulary references, approvals, release exceptions, structured practice-source scope, strict Russian translation coverage, question-image metadata coverage, and Russian explanation alignment evidence. It reads Russian translations, Russian explanations, and question-image metadata from range shards, then checks that the monolithic compatibility indexes are fresh.
- `scripts/content-shards.mjs` owns the deterministic shard loader and generated-index writer for `content/translations/ru/*.json`, `content/explanations/ru/*.json`, and `content/image-metadata/question-images/*.json`. Run `node scripts/content-shards.mjs --write-indexes` after editing a shard, or `node scripts/content-shards.mjs --check-indexes` to detect stale generated indexes.
- `scripts/content-topic-guide.mjs` owns no-file-I/O validation for draft/published topic-study-guide data under `content/guide/topic-study-guide.*.json`, including coverage baseline freshness, topic structure, ticket answer explanations, vocabulary provenance, and draft-safe versus published strict coverage behavior.
- `scripts/official-documents-validation.mjs` owns no-file-I/O validation for the governed official-documents manifest under `content/official-documents/manifest.json`, including required source metadata, local archive paths, SHA-256 hash shape and injected local hash comparison, conversion notes, currentness/effective-status enum fields, exact-text validation enum status, raw evidence for lossy formats, and source-trace checks that current guide claims do not cite missing or not-current documents.
- `scripts/content-image-metadata.mjs` validates generated question-image metadata plus `content/validation/question-image-metadata.evidence.json`. The structural gate requires image-backed questions to have usage mappings, unique image paths to have metadata, fresh path/hash/question fingerprints, approved evidence, and answer-critical detail mappings. The full-quality gate rejects placeholder/baseline/source-image-frame metadata, generic source-image or answer-cue usage, low-confidence required details, approved records without actual visual-review evidence, shared metadata with global relevance/importance keys, missing question-specific relevance maps, and mark-everything-critical usage mappings.
- `scripts/content-explanation-alignment.mjs` validates complete question-card Russian explanation coverage plus `content/validation/ru-explanation-alignment.evidence.json`. It requires correct-answer rationales, wrong-answer rationales, fresh explanation fingerprints, image-detail references for image-backed questions, and structured visual-claim contradiction checks. The full-quality gate also rejects generic filler, Spanish residue, transliteration, and unsupported Latin residue.
- `scripts/content-translation-alignment.mjs` computes stable offline fingerprints for Spanish source tuples and Russian translation tuples, then validates approved local evidence under `content/validation/` so stale, missing, extra, or unaudited translation edits fail preflight without any network, LLM, or runtime service. The full-quality gate rejects draft wrappers, Spanish residue, transliteration, and unsupported Latin residue.
- `scripts/content-difficulty.mjs` computes deterministic offline fingerprints for question and topic difficulty source fields, validates the four-level `green|blue|yellow|red` enum, required dimensions, Russian rationale, provenance, topic basis counts, and stale metadata guards.
- `scripts/content-learning-images.mjs` validates the generated learning-image manifest under `content/learning-images/learning-images.manifest.json`, its stripped runtime projection under `content/learning-images/learning-images.runtime.json`, and `content/validation/learning-images.evidence.json`. It computes current coverage units from topic-study and vocabulary JSON, validates local SVG assets under `content/assets/learning/generated/v1/`, checks hashes/dimensions/alt/provenance, rejects stale fingerprints, question-image replacement paths, and stale or governance-heavy runtime data, and is wired into `pnpm run validate:content`.
- `scripts/content-manual-vehiculo-4ruedas.mjs` validates the complete Russian GCBA 4-wheel manual manifests under `content/manuals/gcba-manual-vehiculo-4-ruedas-2023/`: `manual.ru.json` for exact translation/source coverage, `layout.ru.json` for the static Russian page-layout layer, and `navigation.ru.json` for source-index semantic navigation. It confirms the canonical PDF hash and 200-page count, checks 200 local page-faithful JPEG assets under `content/assets/manuals/gcba-manual-vehiculo-4-ruedas-2023/pages/`, verifies per-page dimensions and SHA-256 checksums, requires exact approved primary-source chunk reuse for pages 1-198 plus visual-label translations for pages 199-200, validates non-generic per-block layout bounds, source-text/source-caption/source-label mask provenance for every page, representative non-Appendix mask coverage, curated Appendix IV sign-mask coverage, meaningful preserved visual regions, and full text reconstruction for all 200 pages, validates navigation ranges/topics from index pages 11-12 plus page-heading/content evidence for Chapter 4 `Стресс` on page 94 and `Отвлечения` on page 95, and scans the runtime manual surface for forbidden PDF viewer, runtime fetch, remote manual asset patterns, the old side-by-side manual selectors, and single-flow transcript rendering. It is wired into `pnpm run validate:content` and exposed as `pnpm run validate:manual-4ruedas`; `--write-derived-manifests` regenerates the committed layout and navigation manifests from the current manual corpus.
- `scripts/render-manual-pdf-pages.swift` is the deterministic local generation helper for the 4-wheel manual page renders. It renders every page from the canonical archived PDF to JPEG assets before runtime; the browser never loads or renders the PDF.
- `scripts/content-source-scope.mjs` owns the practice-source eligibility boundary. Practice questions must reference a source whose `practiceQuestionScope` explicitly allows the question category and uses an allowed scope kind. A/A4/motorcycle-specific source banks are rejected by structured scope, while motorcycle or motovehicle mentions inside valid category B material are allowed as shared-road topics.
- `scripts/refresh-learning-support-evidence.mjs` rebuilds only deterministic validation evidence from the current reviewed shards and generated indexes. Use it after shard edits or integration merges; it does not draft or replace translations, explanations, or image metadata.
- `scripts/generate-learning-support.mjs` is a guarded draft-scaffold helper from the pre-review phase. It can overwrite reviewed learning-support content and now requires explicit `--allow-draft-overwrite`; do not use it for feature 009 completed-content maintenance or integration.
- `scripts/sync-public-assets.mjs` copies committed content assets into Vite public assets before dev/build.
- `scripts/generate-service-worker.mjs` writes a production service worker with the built asset list for offline reload.
- `scripts/content-manual-ticket-placement.mjs` validates the reviewed `Руководство` ticket mapping under `content/manual-ticket-placement/`. It enforces complete `460/460` coverage, `1..3` eligible placements per ticket, exact learner-visible anchors, canonical question/translation/answer/image fingerprints, route and page fingerprints, protected manual source/image hashes, deterministic shards, and separately audited `owner-approved-thematic-fallback` records. Run `pnpm run generate:manual-ticket-placement` only to regenerate deterministic reviewed artifacts and `pnpm run validate:manual-ticket-placement` to fail closed on missing, stale, ineligible, unreviewed, or malformed records.

`pnpm run validate:content` is the structural offline validation used by build. `pnpm run validate:content:quality` enables the feature-009 hard gate and must pass for completed reviewed range shards.

## Official Documents Archive

Official source documents that support topic-guide claims are governed under `content/official-documents/`. See `docs_project/project/content-sources.md` for archive purpose, manifest fields, exact-text preservation rules, currentness/effective-status evidence, raw evidence requirements, and future-document rules.

`scripts/official-documents-exact-text-validation.mjs` performs reproducible live-source exact-text checks for the governed archive. HTML validation builds audited extraction candidates from official `main`/`article`/`body`/document text and rejects subset-only live-source-contained-in-archive matches; PDF validation requires live official bytes to match the retained raw original before text comparison. Evidence `checkedAt` is derived at runtime, and numeric layout cleanup is limited to audited source-format artifacts rather than collapsing arbitrary adjacent digits.

## Deployment

Planned deployment shapes:

- Local Docker-served build for end-user study.
- Optional static hosting of build artifacts (while preserving offline behavior after first load).

## Future Backend Triggers

Backend should only be introduced with an explicit feature spec if requirements add multi-user accounts, sync, remote analytics, or managed content delivery.
