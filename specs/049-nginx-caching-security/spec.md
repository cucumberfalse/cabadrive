## Goal

nginx перестаёт «замораживать» перезагруженный контент под нехешированными путями `/content/assets/` и корректно инвалидирует его в пределах суток, при этом честно immutable-кеширует хешированные Vite-бандлы `/assets/*-<hash>.js|css`. Статический SPA получает базовый security-профиль (строгая `'self'`-only CSP + стандартные защитные заголовки), не ломающий local-first-контракт «no external requests». Текстовые ответы (HTML/JS/JSON/CSS/SVG) отдаются сжатыми gzip. nginx запускается из официального unprivileged-образа (master-процесс не под root) на уже используемом порту 8080. Изменения закреплены двухслойным контрактом: статические text-ассерты на `nginx.conf`/`Dockerfile` в `tests/docker-runtime.test.mjs` (падают на текущем баговом конфиге — test-first) и реальные `curl -I`-проверки заголовков против работающего образа в CI-джобе `docker-validation`. e2e «no external requests» и офлайн-сценарии остаются зелёными. Приложение, SW, роутинг, контент, `assetUrl()` в этом цикле НЕ меняются.

## Background / Current Bugs (проверено на base `c5520b31`; номера строк перепроверить на HEAD)

Весь runtime-конфиг nginx — это `nginx.conf` (20 строк), копируемый в образ как `/etc/nginx/conf.d/default.conf` (`Dockerfile:15`). Текущее состояние (`nginx.conf` на base `c5520b31`):

- **Баг №1 — инвертированная кеш-политика.** `location /content/assets/` (`nginx.conf:11-14`) отдаёт `add_header Cache-Control "public, max-age=31536000, immutable"`, хотя пути под `/content/assets/` НЕ хешированные: `assetUrl(localPath)` в `src/data/content.ts:383-385` просто префиксует слэш (`return \`/${localPath}\``), то есть фото билетов/кропы/картинки вопросов живут под стабильными именами (`page-001.jpg` и т. п.). Пере-загруженная под тем же путём картинка не доедет до клиентов год (даже смена имени SW-кеша не поможет: новый прекеш-`fetch` удовлетворится из HTTP-кеша браузера теми же устаревшими `immutable`-байтами). При этом действительно immutable хешированные Vite-бандлы `/assets/*-<hash>.js|css` НЕ имеют явного `Cache-Control` вовсе — в `nginx.conf` нет `location /assets/`. То есть immutable стоит ровно там, где он вреден, и отсутствует там, где уместен.
- **Баг №2 — нет security-заголовков.** CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` полностью отсутствуют.
- **Баг №3 — нет сжатия.** `gzip` в конфиге не включён; мегабайтные JSON-несущие JS-чанки контента отдаются несжатыми — прямое замедление первой загрузки и установки оффлайна.
- **Баг №4 — образ под root.** Runtime-стадия — `FROM nginx:1.29-alpine` (`Dockerfile:13`): master-процесс nginx работает от root. Порт уже `8080` (`Dockerfile:18` `EXPOSE 8080`, `nginx.conf:2` `listen 8080`), совместимо с unprivileged-образом из коробки.

Контрактный слой сейчас: `tests/docker-runtime.test.mjs` (4 `test()` блока, строки 16-53) статически проверяет только текст `docker-compose.yml`/`Makefile`/`docs_project/…/docker-runtime.md`/`frontend-docs.md` и НЕ читает `nginx.conf`/`Dockerfile` и не делает HTTP-проверок заголовков; CI-джоба `docker-validation` (`.github/workflows/ci.yml:100-129`) поднимает образ и делает runtime-smoke `curl /` (строка 119) и `curl /sw.js` (строка 125), но заголовки не проверяет.

Верификация build-вывода (Architect, HEAD): `corepack pnpm@10.33.0 run build:app` → `dist/index.html` содержит РОВНО `<script type="module" crossorigin src="/assets/index-<hash>.js">` и `<link rel="stylesheet" crossorigin href="/assets/index-<hash>.css">`. Инлайн-`<script>` без `src`, `on*`-хендлеров и внешних origin в сборке НЕТ (modulepreload-polyfill Vite инжектится как module-import внутри entry-чанка, а не инлайн в HTML). Значит `script-src 'self'` безопасен, а `style-src 'self' 'unsafe-inline'` покрывает и линкованный `/assets/*.css` (`'self'`), и рантайм-инлайн-стили React/Vite (`'unsafe-inline'`).

## Functional Requirements

1. **FR-1.1 (split кеш-политики).** Ответ на хешированный путь `/assets/*-<hash>.js|css` несёт `Cache-Control: public, max-age=31536000, immutable`. Ответ на нехешированный путь `/content/assets/…` несёт `Cache-Control: public, max-age=86400, stale-while-revalidate=604800` и НЕ содержит `immutable`. `/sw.js` несёт `Cache-Control: no-cache`. `location /` сохраняет `try_files $uri $uri/ /index.html`; `location /assets/` и `location /content/assets/` возвращают `=404` для отсутствующего ассета (без SPA-фолбэка на HTML).
2. **FR-2.1 (security-заголовки на ВСЕХ ответах).** На каждом ответе (`/`, `/assets/`, `/content/assets/`, `/sw.js`, а также ошибочные 404) присутствуют `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()` и CSP ровно вида `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; base-uri 'none'; frame-ancestors 'none'`. Эмиссия на ошибочных ответах гарантируется `always`.
3. **FR-2.2 (`'self'`-only CSP).** CSP не содержит ни одного внешнего origin/CDN (`'self'`-only + `data:` для `img-src`) — чтобы не ввести внешний запрос и не сломать e2e «no external requests».
4. **FR-2.3 (нет white-screen).** `script-src 'self'` совместим с текущей сборкой (единственный скрипт — module-`<script src="/assets/…">`; инлайн-скриптов нет, подтверждено build-выводом). `style-src 'unsafe-inline'` оставлен под рантайм-инлайн-стили Vite/React; линкованный `/assets/*.css` покрыт `'self'`.
5. **FR-3.1 (gzip).** `gzip on`, `gzip_vary on`, `gzip_min_length 1024`, `gzip_comp_level 6`; `gzip_types` включает `text/javascript` (тип, в который nginx 1.29 mime.types мапит `.js`/`.mjs`), а также `application/javascript`, `application/json`, `image/svg+xml`, `text/css`. При запросе с `Accept-Encoding: gzip` ответ на текстовый ресурс (JS-чанк ≥1024 байт) содержит `Content-Encoding: gzip`. `text/html` НЕ перечислен явно (сжимается неявно; явное перечисление вызвало бы warning «duplicate MIME type text/html»).
6. **FR-4.1 (unprivileged-образ).** Runtime-стадия `Dockerfile` — `FROM nginxinc/nginx-unprivileged:1.29-alpine`; контейнер стартует и обслуживает на `:8080`; master-процесс nginx НЕ под root. Пути `COPY nginx.conf /etc/nginx/conf.d/default.conf` и `COPY --from=build /app/dist /usr/share/nginx/html`, `EXPOSE 8080`, `CMD ["nginx","-g","daemon off;"]` сохранены (образ решает pid `/tmp/nginx.pid` и не-root пользователя `nginx` uid 101 из коробки). Build-стадия `node:22-alpine` не меняется.
7. **FR-5.1 (статический контракт — test-first regression guard).** `tests/docker-runtime.test.mjs` расширен статическими text-ассертами на `nginx.conf` и `Dockerfile`, которые ПАДАЮТ на текущем баговом конфиге (immutable на `/content/assets/`, отсутствие `/assets/`-immutable, отсутствие security-заголовков/CSP/gzip, стоковый `nginx:1.29-alpine`) и проходят на исправленном: `/assets/` = immutable; `/content/assets/` = `max-age=86400`+`stale-while-revalidate` без immutable; наличие всех security-заголовков + точной CSP; `gzip_types` включает `text/javascript`; base image `nginxinc/nginx-unprivileged`.
8. **FR-5.2 (runtime-контракт — `curl -I` на живом образе).** CI-джоба `docker-validation` расширена реальными `curl -I`-проверками против поднятого образа: `immutable` на хешированном `/assets/*.js`; ОТСУТСТВИЕ `immutable` + `max-age=86400` на `/content/assets/`-картинке; `X-Content-Type-Options: nosniff`; наличие CSP-заголовка; `Content-Encoding: gzip` при `Accept-Encoding: gzip` на JS-ассете. Существующие smoke `curl /` и `curl /sw.js` сохранены.
9. **NFR-1 сохранён.** e2e «no external requests» (`tests/e2e/app.spec.ts:1918-1934` и параллельные ~2223/~2307) и офлайн-сценарии зелёные: CSP `'self'`-only не вводит внешний origin, кеш-политика не ломает офлайн-прекеш.

## Negative Scenarios (обязательны для feature memory)

- **NS-1 — строгая CSP ломает инлайн-стили Vite/React → белый экран.** Мера: `style-src 'unsafe-inline'` оставлен в CSP; аудит консоли (grep инлайн + build-вывод: инлайн-скриптов/`on*` нет) до enforce; AC-2 (ноль CSP-violation). `script-src 'self'` без `'unsafe-inline'` безопасен, потому что инлайн-скриптов нет. Проверяемо: AC-2 + инвариант текста CSP.
- **NS-2 (главный) — `/content/assets/` НЕ должен быть `immutable` (регресс-guard сути ТЗ).** Нехешированная перезагруженная картинка не должна «залипать» на год. Ответ на `/content/assets/…` обязан нести `max-age=86400`+`stale-while-revalidate=604800` и НЕ содержать `immutable`; параллельно `/assets/` = `immutable`. Проверяемо: статический контракт (FR-5.1) обязан падать на текущем баговом конфиге (где `/content/assets/`=immutable) + runtime `curl -I` (FR-5.2). Подтверждено Architect: текущий `nginx.conf` не содержит ни `map $uri $cache_control`, ни `/assets/`-immutable-маппинга, ни `content/assets/`-`max-age=86400`-строки → все новые ассерты падают на нём.
- **NS-3 — unprivileged-образ не стартует / master под root.** Переход меняет pid/read-пути и дефолтного пользователя. Мера: официальный образ решает пути из коробки (pid `/tmp/nginx.pid`, `USER nginx`); наши `COPY`/`listen 8080`/`CMD` без изменений; docker-smoke подтверждает старт и обслуживание на :8080, AC-4 — не-root. Проверяемо: контейнер отвечает на `curl /` и `/sw.js`; статический контракт фиксирует base image.
- **NS-4 — security-заголовки вводят внешний origin и ломают e2e «no external requests».** Мера: CSP строго `'self'`-only (+`data:` img), никаких внешних директив; e2e «no external requests» остаётся зелёным как guard. Проверяемо: NFR-1 (e2e зелёный) + инспекция текста CSP (нет `http(s)://`-origin).
- **NS-5 — header-контракт «косметический» (по тексту конфига, не на живом образе).** Мера: двухслойность FR-5 — статический контракт (test-first, падает на баговом) + реальный `curl -I` на поднятом образе в CI. Проверяемо: AC-5 (наблюдаемое падение статики на баговом) + AC-1 (curl -I).
- **NS-6 — gzip настроен, но не срабатывает (тип/`min_length`).** Ключевой риск: nginx 1.29 mime.types мапит `.js`/`.mjs` в `text/javascript`, а НЕ `application/javascript`; если `gzip_types` не включает `text/javascript`, JS-бандлы отдаются несжатыми. Мера: `gzip_types` включает `text/javascript` (и `application/javascript` для страховки); `gzip_min_length 1024`; runtime-проверка `Content-Encoding: gzip` на JS-чанке при `Accept-Encoding` (FR-5.2). Проверяемо: AC-1 (curl -I gzip) + статический ассерт наличия `text/javascript` в `gzip_types`.
- **NS-7 — `add_header`-inheritance trap стирает security-заголовки на ассетах.** В nginx `add_header` в `location`-блоке ОТМЕНЯЕТ наследование server-level `add_header` для этого location. Наивная схема (security-заголовки в `server{}`, `Cache-Control` в `location /assets/`) молча уронила бы security-заголовки на всех ассет-ответах. Мера: Cache-Control выведен из `map $uri $cache_control` + единственный server-level `add_header Cache-Control $cache_control always;`; ни в одном `location` НЕТ `add_header` → server-level заголовки наследуются всеми ответами. Проверяемо: runtime `curl -I` на `/assets/`- и `/content/assets/`-путях показывает и security-заголовки, и корректный Cache-Control (FR-5.2, AC-1).

## Assumptions (из intake A1–A9; Architect-подтверждены/уточнены)

- **A1 — форма `Cache-Control`.** `/content/assets/` = `public, max-age=86400, stale-while-revalidate=604800` дословно (ТЗ-14 §3 FR-1). Реализация — через `map $uri $cache_control` + единственный server-level `add_header Cache-Control $cache_control always;` (см. Decisions «header-inheritance»), а не через per-location `add_header`.
- **A2 — CSP report→enforce.** В финальном образе CSP — enforce (`Content-Security-Policy`, не `-Report-Only`). «Report-режим» ТЗ-14 §4 реализуется как ЛОКАЛЬНАЯ верификация (browser console + e2e AC-2), а не как отдельный committed report-only-заголовок или отдельный коммит. Один PR, без промежуточного report-only-шага (сборка не содержит инлайн-скриптов → enforce безопасен сразу).
- **A3 — CSP-директивы дословно.** `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'; connect-src 'self'; base-uri 'none'; frame-ancestors 'none'` — символ-в-символ. `object-src`/`form-action` НЕ добавляются (минимальная площадь, детерминизм FR-5 ассертов; текущая CSP уже жёстко ограничивает через `default-src 'self'`). `'unsafe-inline'` для `script-src` НЕ добавляется.
