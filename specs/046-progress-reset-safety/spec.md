# Спецификация: Безопасный сброс прогресса — подтверждение, undo, экспорт/импорт

## Goal

Реализовать слайс 1 `ТЗ-P1` (FR-A1 + FR-A2 + FR-A3) одним PR: ни один тап по
кнопке «Сбросить прогресс» не приводит к безвозвратной потере данных. Сброс
выполняется только после явного информированного подтверждения в модальном
диалоге с реальными счётчиками, отменим до конца сессии браузера через
undo-снапшот в sessionStorage, а пользователь получает штатный экспорт/импорт
прогресса JSON-файлом поверх существующего строгого API store из PR #210.

## Поведенческий контракт

### FR-A1 — подтверждение сброса

1. Кнопка шапки `aria-label="Сбросить прогресс"` больше никогда не вызывает
   `dispatchProgress({ type: "reset" })` напрямую: клик открывает модальный
   `ConfirmDialog` через `dialog.showModal()`.
2. Диалог перечисляет удаляемое в реальных числах из одного снапшота
   `useProgress()` на момент открытия:
   - N — `progress.answers.length` («сохранённых ответов»; метрика явно
     названа как retained-история, pruned-агрегат в число не входит);
   - M — `mistakesFromProgress(progress).length` («вопросов с ошибками» — та
     же метрика, что «тем для повторения» в StatusStrip);
   - K — `progress.examAttempts.length` («попыток экзамена»).
3. Двойное подтверждение (допущение A1, текстовый ввод отклонён как
   мобильно-враждебный): чекбокс «Я понимаю, что данные будут удалены»
   активирует деструктивную кнопку «Удалить прогресс» (до отметки —
   `disabled`). Состояние чекбокса сбрасывается при каждом открытии диалога.
4. Безопасная кнопка «Отмена» получает автофокус при открытии (NFR-3).
   Фокус-ловушка и Esc — нативные для `showModal()`; Esc обрабатывается через
   событие `cancel`, клик по backdrop закрывает диалог как отмену. Любой
   способ отказа (Отмена, Esc, backdrop) не меняет ни состояние store, ни
   localStorage-ключи.
5. Подтверждение: перед `reset` выполняется попытка записи undo-снапшота
   (FR-A2); затем `dispatchProgress({ type: "reset" })`; диалог закрывается;
   фокус возвращается на кнопку сброса (нативное поведение `<dialog>`).

### FR-A2 — undo сброса до конца сессии

1. Снапшот — строка канонического v2 `exportProgress()`, записывается в
   sessionStorage под новым ключом `cabadrive.progress.reset-undo.v1`
   (допущение A2) непосредственно перед деструктивной операцией (reset или
   применение импорта). Запись — в try/catch (`saveUndoSnapshot` возвращает
   `boolean`).
2. После успешного сброса с записанным снапшотом под шапкой (над StatusStrip)
   отображается статус-панель с `role="status"` (полит-live-регион): текст
   «Предыдущий прогресс сохранён — его можно вернуть до конца сессии.»,
   кнопка «Вернуть» и кнопка «Скрыть».
3. «Вернуть» → `dispatchProgress({ type: "importProgress", raw: snapshot })`
   (допущение A3 — существующий строгий атомарный путь; отдельного
   restore-действия в store нет). При `true`: снапшот удаляется из
   sessionStorage, панель скрывается, live-регион объявляет «Прогресс
   восстановлен.». Снапшот одноразовый: повторное нажатие невозможно, а сам
   импорт — замещение, поэтому дубликаты записей исключены дважды.
4. «Скрыть» — явный отказ пользователя от undo: снапшот удаляется, панель
   скрывается (зафиксированное решение; молчаливое сохранение ключа при
   скрытой панели создало бы недостижимый UX-путь).
5. Перезагрузка страницы той же вкладки до undo: при монтировании App читает
   ключ; если снапшот существует — панель с «Вернуть» отображается снова
   (снапшот переживает reload, семантика sessionStorage).
6. sessionStorage недоступен/переполнен (private mode, квота): запись
   снапшота возвращает `false`, сброс после подтверждения всё равно
   выполняется, но вместо undo-панели показывается статус-панель
   «Прогресс сброшен. Отмена недоступна: хранилище сессии недоступно.»
   без кнопки «Вернуть». Приложение не падает.
7. Конец сессии браузера очищает sessionStorage — undo истекает штатно, без
   собственного кода очистки по таймеру.

### FR-A3 — экспорт/импорт прогресса JSON-файлом

1. В шапке рядом с кнопкой сброса — группа из трёх icon-кнопок (допущение
   A8): «Экспортировать прогресс» (иконка Download), «Импортировать прогресс»
   (иконка Upload), «Сбросить прогресс» (RotateCcw, существующая). Русские
   `aria-label`/`title` в стиле шапки; каждая кнопка ≥42 px.
2. Экспорт: `exportProgress()` → `Blob` типа `application/json` →
   `URL.createObjectURL` → временный `<a download>` → клик →
   `URL.revokeObjectURL`. Имя файла —
   `cabadrive-progress-<YYYY-MM-DD>.json` по локальной дате (допущение A5,
   функция `exportFileName(date)`). Без подтверждения — экспорт
   недеструктивен. Без новых зависимостей.
3. Импорт: кнопка активирует скрытый `<input type="file"
   accept="application/json,.json">`. Файл читается как текст, затем
   предвалидация `parseImportedProgress(text)` (публичный API store):
   - `undefined` (не-JSON, чужая схема, неизвестная `version`, битые
     вложенные записи) → состояние не меняется, показывается панель ошибки
     с `role="alert"`: «Не удалось импортировать файл: это не корректный
     экспорт прогресса Cabadrive. Текущий прогресс не изменён.» с кнопкой
     «Скрыть». Значение input сбрасывается (тот же файл можно выбрать
     повторно после исправления).
   - валидный `ProgressV2` → `ConfirmDialog` замещения (допущение A4:
     подтверждение И undo-снапшот): текст перечисляет текущие N/M/K и
     счётчики файла (N′ ответов, K′ попыток экзамена). Автофокус на
     «Отмена»; чекбокс двойного подтверждения не требуется — операция
     обратима через undo. Кнопка подтверждения — «Импортировать».
4. Подтверждённый импорт: undo-снапшот текущего состояния (механизм FR-A2) →
   `dispatchProgress({ type: "importProgress", raw: text })`. При `true` —
   панель undo с «Вернуть»; при `false` (гонка/деградация после
   предвалидации) — та же панель ошибки импорта, состояние не изменено.
5. Round-trip гарантия: файл, экспортированный на одном профиле,
   импортируется на чистом профиле с полным восстановлением ответов, ошибок
   и попыток экзамена (AC-6 ТЗ-06 — канонический v2).
6. UI не обращается к localStorage-ключам прогресса напрямую — только
   публичный API `src/progressStore.ts`; sessionStorage-ключ undo — только
   через `src/progressResetSafety.ts`.

## Acceptance Criteria

1. Тап по «Сбросить прогресс» без подтверждения не удаляет данные: диалог
   открыт, «Отмена»/Esc/backdrop закрывают его, счётчики StatusStrip и
   значение `localStorage["cabadrive.progress.v1"]` не изменились (e2e).
2. Диалог сброса показывает фактические N/M/K из текущего состояния store;
   кнопка «Удалить прогресс» неактивна до отметки чекбокса (e2e).
3. Подтверждённый сброс очищает прогресс и показывает панель с «Вернуть»;
   нажатие «Вернуть» полностью восстанавливает ответы, ошибки и попытки
   экзамена — счётчики StatusStrip совпадают с состоянием до сброса (e2e).
4. Перезагрузка страницы после сброса, но до undo, сохраняет доступность
   «Вернуть» в той же вкладке (e2e или unit + зафиксированное ручное
   свидетельство).
5. export → reset → import восстанавливает прогресс: скачанный файл имеет имя
   `cabadrive-progress-<YYYY-MM-DD>.json`, его импорт на очищенном состоянии
   возвращает исходные счётчики (e2e, AC-1 ТЗ-P1).
6. Импорт битого JSON (не-JSON, чужая схема, неизвестная `version`) не меняет
   текущий прогресс, показывает человекочитаемую ошибку с `role="alert"`;
   после «Скрыть» приложение полноценно работает (e2e — главный негативный
   сценарий цикла).
7. A11y диалога: Esc закрывает без изменений, фокус заперт внутри, автофокус
   на «Отмена» (e2e-проверки `document.activeElement`/focusable-обход и/или
   ручной чеклист с зафиксированным результатом).
8. При недоступном sessionStorage сброс после подтверждения выполняется,
   пользователь видит предупреждение об отсутствии undo, исключений в
   консоли нет (unit на `saveUndoSnapshot`; e2e-вариант опционален).
9. Двойное «Вернуть» не задваивает данные: после успешного восстановления
   снапшот удалён и панель скрыта (unit + e2e-наблюдение).
10. Существующий e2e-набор зелёный в обоих проектах; `pnpm run test`,
    `pnpm run quality:fast`, `pnpm run format:check`, `pnpm run build:app`,
    `pnpm run preflight` зелёные; grep-свидетельство: в `src/` вне
    `progressResetSafety.ts` нет обращений к `sessionStorage`, вне
    store-границы нет обращений к localStorage-ключам прогресса.

## Негативные сценарии (обязательные)

- Случайный одиночный тап по RotateCcw ничего не удаляет.
- Импорт битого/чужого JSON не портит и не очищает текущий прогресс
  (главный негативный сценарий).
- Отказ от диалога любым способом (Отмена/Esc/backdrop) — noop для store и
  localStorage.
- sessionStorage недоступен: сброс работает, предупреждение показано,
  приложение не падает.
- Reload после сброса до undo не теряет путь «Вернуть».
- Повторное «Вернуть» невозможно после успешного восстановления.
- `dispatchProgress({ type: "importProgress" })` вернул `false` после
  успешной предвалидации — показана ошибка, состояние не изменено.
